01 / COMPUTER VISION

Catwatch

Understanding what the camera sees.

Detect a cat. Inspect a prediction. Correct what the model gets wrong.

Problem. A behavior label is only useful if the user can see when the model is uncertain.

Built. A local desktop app with cat detection, a session timeline, uncertainty handling, and explicit corrections. Inference runs in a worker to keep the interface responsive.

Evidence. 37.9% accuracy on 543 held-out MEOW-10K clips, compared with a 19.0% majority baseline. This measures dataset performance, not live-camera accuracy.

Explore walkthrough ↗

Scripted browser demo; no camera access or live inference.

Model evaluation & technical notes +

A frozen MobileNetV3 encoder feeds a class-balanced ridge classifier over pooled visual features. On 543 held-out MEOW-10K clips, it achieved 37.9% accuracy against a 19.0% majority baseline. These dataset results do not establish live-camera accuracy.

Feedback is saved explicitly and does not automatically retrain the model. A separate earlier CLI pipeline handles rule-based events and optional AWS storage and notifications.

Python / PyTorch / YOLOv8 / PySide6 / OpenCV

02 / GEOSPATIAL APPLICATION

Straydar

A sighting becomes a shared record.

Helping neighbors connect the dots around stray and missing cats.

Problem. Separate sightings can describe the same cat, scattering useful information across reports.

Built. A shared map, community feed, and missing-cat reporting flow with persistent records and realtime updates.

RESULT / EXPLAINABLE MATCHING

Match before duplicating.

Nearby sightings within 150 meters are grouped by cat, then ranked using temperament and shared description terms. Suggestions have an explainable reason behind them.

Rescue guidance & implementation notes +

The rescue assistant provides predefined guidance with optional Claude responses. Emergency vet information comes from OpenStreetMap with a fallback list. Matching is deterministic, not machine learning.

This is a development-stage application; authentication and access policies still need production hardening.

03 / SPORTS DATA PLATFORM

Match Tracker

Five leagues. One place to follow them.

Keep the match history. Make the next fixture easier to explore.

Problem. Provider windows limit how far back match data stays available.

Built. A React dashboard and Flask API with SQLite history, cached provider requests, team-form analysis, and Elo estimates.

Result. Retained results support form analysis beyond the provider’s rolling window. Five leagues share one interface; prediction accuracy remains unvalidated.

Live site ↗Source ↗
Data sources & model limitations +

Provider clients combine football-data.org, API-Football, FotMob lineups, and Google News RSS. Backend pytest and frontend Vitest suites run in GitHub Actions.

The Elo model processes the previous 90 days of completed matches, with a fixed home-advantage adjustment. Its estimates are two-way and do not include a separate draw probability; predictive accuracy has not been validated.

React / Flask / SQLite / REST APIs / pytest / Vitest
